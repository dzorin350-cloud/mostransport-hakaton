# Заметка для фронтенда: что учитывает модель и что показывать пользователю

Статус: задача в работу фронтенду. Кнопки и раскладка интерфейса ещё меняются — здесь только **что** показывать, а не как.

## Как считается прогноз

**прогноз(маршрут, дата, час) = уровень маршрута × форма дня × сезонный множитель месяца × корректирующий коэффициент**

## Что учитывает модель

| Фактор | Источник | Что делает | Показывать пользователю |
|---|---|---|---|
| Уровень маршрута | собственные валидации, последние 56 дней до даты данных | масштаб прогноза (посадок в сутки) | «База: N посадок/сутки, по данным до ДД.ММ.ГГГГ» |
| Форма дня (часы пик, будни/выходные) | собственные валидации: модель CatBoost + профиль последних 2 недель | распределение по часам и дням недели | график по часам, пиковый час |
| Праздники, переносы, рабочие субботы, дни до/после выходных | производственный календарь РФ, [isdayoff.ru](https://isdayoff.ru) | праздничный будень считается как воскресенье; рабочая суббота — среднее пятницы и субботы | пометка дня: «праздник», «перенос», «предпраздничный» |
| Сезонность месяца и рост | месячный пассажиропоток трамвая Москвы, [data.mos.ru, набор 62521](https://data.mos.ru/opendata/62521) | множитель месяца относительно месяца последних данных | «Сезонный множитель: ×0,88 (январь)» |
| Очистка истории от ремонтов, перекрытий, сбоев | автоматически по данным; подтверждено объявлениями Дептранса ([t.me/s/DtOperativno](https://t.me/s/DtOperativno)) | модель учится на нормальной работе маршрута | в справке: «прогноз предполагает штатную работу маршрута» |
| Корректирующий коэффициент | интерфейс (погода, событие, ручная поправка) | множитель поверх прогноза без переобучения | текущее значение и что именно применено |

## Что модель НЕ учитывает (показывать в справке/подсказке)
- будущие ремонты, перекрытия, изменения маршрутов — только через ручной коэффициент;
- погоду в конкретный день (эффект измерен по метеостанции Москва-ВДНХ: дождливый день ≈ −3…−4 % посадок; кнопка «Дождь» уже поставлена ×0,96);
- массовые события;
- на горизонте больше 2–3 месяцев — индивидуальную сезонность маршрута (все маршруты получают городскую) и летнюю перестройку часов пик.

## Надёжность по горизонту (показывать, чтобы пользователь понимал точность)
По бэктестам на реальных данных 2025 (WAPE-score, 1 = идеально):

| Горизонт | Точность |
|---|---|
| 1 месяц | ≈ 0,87 |
| 2 месяца (ноябрь–декабрь, лидерборд) | 0,884 |
| 3–5 месяцев | ≈ 0,84–0,85 |
| 12 месяцев (город целиком, по месяцам) | ≈ 0,93–0,97 |

Предложение: помечать дальний горизонт («прогноз на > 3 месяцев — ориентировочный») и, когда бэкенд начнёт отдавать коридор, рисовать его заливкой вокруг линии прогноза.

## Метаданные API
Уже есть:
- `GET /model/info` — `data_until`, `horizon` (start/end — брать отсюда границы выбора дат вместо зашитых в HTML),
  `month_multipliers` (сезонный множитель по месяцам), `year_shape_months`, `sources` (откуда внешние данные:
  `live` / `cache` / `fallback`), `computed_at`;
- в ответе `/forecast`: `data_until`, `model_version`;
- `granularity=week` для недельной агрегации.

Ещё нет (к согласованию с бэкендом): тип дня по датам (будний/выходной/праздник/перенос), `interval` — коридор прогноза.

Прогноз строит сам сервис (движок, `service/engine/`), горизонт — 12 месяцев от даты данных; при появлении новых данных он сдвигается автоматически.

## Уже сделано в `service/web/index.html` (прототип, можно переделать)
- Окно входа и регистрации открывается первым; токен хранится в `localStorage`, все запросы идут с заголовком `Authorization`;
  при 401 — снова окно входа; в шапке логин и «выйти».
- Границы выбора дат и кнопки «День / Месяц / Год» берутся из `/model/info` (`horizon`), в шапке — «Данные до …».
- Экспорт скачивается через `fetch` с токеном (прямая ссылка без токена больше не работает).

## Остановки и погода (новое)
- `GET /stops?route=` — GeoJSON остановок (название, маршруты) для маркеров на карте.
- `GET /forecast/stops?date_from&date_to&route&hour_from&hour_to&coefficient` — посадки по остановкам за период
  (размер или цвет маркера). Доли остановок зависят от времени суток (утро/день/вечер/ночь), поэтому при выборе часов
  картинка меняется. В ответе поле `note` — обязательно показать пользователю: разбивка **оценочная**.
- В `/model/info` — `rain_adjusted_days`: дни, где прогноз снижен из-за ожидаемого сильного дождя (можно помечать значком).

## Новое: коридор, вагоны, мониторинг, демо-аккаунт
- В `/forecast` у каждой строки `lo` и `hi` — коридор 80 % (заливка вокруг линии прогноза); пояснение — поле `interval`.
- `GET /fleet` — по часам: `prediction`, `veh_typ` (обычно вагонов), `bpv` (посадок на вагон), `load_index`, `status`
  («норма» / «повышенная» / «риск переполнения» — светофор на карте и в таблице), `veh_recommended`, `veh_delta` (+добавить / −можно снять),
  `summary` по маршрутам и `total` (вагоно-часы обычно / рекомендовано, часов с риском). Показать `note`.
- `GET /monitor/accuracy` — факт против прогноза по дням и маршрутам (для экрана «качество прогноза»).
- Демо-аккаунт `demo` / `demo2025` — можно подставить подсказкой в окне входа.

## Режим «Сейчас», демо-время, алерты и подсказки (новое — задача фронтенда)

### Демо-время
Стенд работает на данных до 31.10.2025, поэтому «сегодня» — виртуальная дата, а **время суток — пользователя**.
- `GET /model/info` → `now_mode` (`demo` на стенде, `real` в проде) и `demo_today` (по умолчанию `2025-11-01` — первый день прогноза, рабочая суббота).
- Шапка: «Демо-время: 01.11.2025, 14:32 — дата сдвинута к периоду прогноза, время ваше» (текст — `help.demo_time` из `/now`). В проде — обычная дата и время.
- Переключатель демо-даты (только в режиме `demo`): выбор дня в пределах `horizon`; передавать в `/now` и `/alerts` параметром `date`.
  Интересные дни для показа: `2025-11-01` (перенос, сокращённый), `2025-11-03` (праздник), `2025-11-12` (сильный дождь, будни), `2025-12-30` (перед Новым годом).

### `GET /now?hour=<час пользователя>&date=<демо-дата>&route=<маршруты>`
Час брать с часов браузера (`new Date().getHours()`), обновлять раз в минуту, при смене часа — перезапрашивать.

### `GET /alerts?hour=&date=&lookahead=3`
Список предупреждений, уже отсортирован: `критично` → `внимание` → `инфо`. Поля: `level`, `type`, `text` (готовый текст для диспетчера),
при наличии — `route`, `hours`, `veh_delta`, `date`.

| type | Когда | level |
|---|---|---|
| `переполнение` | риск переполнения в ближайшие `lookahead` часов | критично |
| `повышенная загрузка` | загрузка выше 85 % порога | внимание |
| `избыток вагонов` | можно снять ≥ 3 вагонов без роста интервалов > 1,7 раза | инфо |
| `календарь` | праздник / перенос / сокращённый день сегодня и 7 дней вперёд | внимание (сегодня) / инфо |
| `погода` | сильный дождь по прогнозу погоды (на стенде — демо по архиву) | инфо |
| `данные` | фактические данные старше 2 дней: прогноз дальше, коридор шире | внимание |
| `пересчёт` | движок не смог обновить прогноз, действует прошлая версия | критично |
| `точность` | WAPE-score за последние 7 дней ниже 0,85 (когда есть факты) | внимание |

### Что сделать в интерфейсе (предложение)
1. **Шапка:** демо-время, дата данных (`data_until`), значок «демо» в режиме `demo`.
2. **Блок «Сейчас»:** посадок в текущем часу по сети с коридором (`network.now`, `now_lo`–`now_hi`), «за день ожидается / уже прошло»
   (`day_total`, `day_passed`), число маршрутов с риском.
3. **Карта «сейчас»:** цвет линии маршрута — `routes[].now.status` (норма — зелёный, повышенная — жёлтый, риск — красный);
   кружки остановок — `/forecast/stops` за текущий час.
4. **Лента ближайших часов:** столбики `routes[].next` с коридором, отметка статуса; клик по маршруту — детализация `/fleet` на день.
5. **Панель алертов:** `/alerts`, цвет по `level`, клик — выбор маршрута и часа на карте.
6. **Подсказки «i»** у показателей — тексты из `help` (`/now`), `note` (`/fleet`, `/forecast/stops`), `interval` (`/forecast`).
7. **Карточка маршрута:** сейчас вагонов `veh_typ`, нужно `veh_recommended`, разница `veh_delta` (+ добавить / − можно снять).

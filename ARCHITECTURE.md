# Архитектура решения: прогноз посадок в трамваях Москвы

**Итоговая модель, WAPE-score на лидерборде 0,88835** (порог максимального балла «> 0,88» пройден).

Задача: почасовой прогноз посадок (успешных валидаций) на 10 маршрутах трамвая (1, 5, 7, 11, 12, 17, 25, 26, 28, 50)
на 01.11–31.12.2025, 14 640 строк. Метрика: WAPE-score = 1 − Σ|y − ŷ| / Σy. Обучающие данные — январь–октябрь 2025.
Решение — модель и веб-сервис, который сам применяет её к поступающим данным и превращает прогноз в решения диспетчера.

**Почему запросы не запускают модель.** Прогноз меняется только при поступлении данных, поэтому движок считает его один раз
(≈ 25 с), а воркеры API держат готовую таблицу в памяти и отдают срезы: сотни–тысяча RPS при p95 в миллисекундах
([PERFORMANCE_AND_FEATURES.md](docs/PERFORMANCE_AND_FEATURES.md)). Сценарные коэффициенты применяются множителем поверх
готового прогноза — это позволяет мультипликативная структура модели (§2).

**Путь данных и запроса.** Новые валидации (`POST /ingest/*` или файл истории) → движок замечает их в течение минуты →
пересчёт (≈ 25 с) → новая версия записывается в отдельный каталог и становится текущей одной атомарной заменой указателя →
воркеры API подхватывают её без перезапуска; прошлая версия остаётся в архиве для контроля точности. Запрос диспетчера
(`/plan`, `/alerts`) берёт срез прогноза из памяти, добавляет нормы вагонов и сценарий и кэшируется по версии прогноза.

## 2. Модель

**Прогноз = уровень маршрута × форма дня × сезонный множитель месяца**; обучение — на данных, очищенных от перекрытий,
объединений маршрутов и других разовых сбоев. Артефакты, код и запуск — [docs/MODEL.md](docs/MODEL.md).

```
Валидации 2025 (62 млн строк)                     Месячный пассажиропоток трамвая Москвы
        │ успешные, агрегат маршрут × дата × час      (data.mos.ru 62521, 2019 – окт 2025)
        ▼                                                          │
Почасовая сетка (9 маршрутов × 304 дня × 24 ч)                     │
        ▼                                                          │
ОЧИСТКА ОБУЧЕНИЯ: аномальные маршруто-дни → «нормальное» значение  │
        ├──► уровень маршрута L: посадок в сутки, последние 56 дней │
        ├──► CatBoost: доля от уровня по (маршрут, час, день недели,│
        │    выходной, праздничный будень, до/после выходных),      │
        │    2 набора × 5: базовый и + длина светового дня          │
        ├──► Профиль: медиана (маршрут × день недели × час), 4 нед. │
        ▼                                                          ▼
   Форма дня: будни 0,6·CB + 0,4·профиль;             Сезонный множитель месяца:
   выходные 0,8·CB + 0,2·профиль;                     среднее отношение «месяц / базовый месяц»
   праздничные будни — только CB                      за 2019, 2021–2024 (2020 исключён)
        └──────────────────────────► × ◄───────────────────────────┘
                                     ▼
                  прогноз маршрут × дата × час (маршрут 5 = 0)
```

| Компонент | Что делает | Параметры |
|---|---|---|
| Подготовка | успешные валидации (`validation_result = 1`) → почасовая сетка; маршрут из `ngpt_route`, время из `tran_date_time`; пустые часы = 0 | duckdb, parquet |
| **Очистка обучения** | недели со сдвигом доли маршрута в сети > 15 % и дни вне ×1,5 от медианы того же типа дня (±5 недель) заменяются медианой × обычная почасовая доля; праздники не трогаются. Помечено 168 маршруто-дней; крупные аномалии совпадают с объявлениями Дептранса о перекрытиях | порог 1,5; 15 % |
| Календарь | день недели, выходной / праздник, праздничный будний день, рабочий день до / после выходных — по производственному календарю isdayoff.ru | |
| Уровень маршрута | среднее посадок в сутки за 56 дней очищенных данных | 56 дней |
| CatBoost | цель — доля часа от скользящего 42-дневного уровня, вес строки — уровень; 5 seed | RMSE, 800 итераций, глубина 8, lr 0,049, l2 12; Optuna, 148 проб |
| Профиль | медиана «маршрут × день недели × час» за 4 недели без праздничных будней | 4 недели, медиана |
| Сезонный множитель | отношение суточного пассажиропотока трамвая Москвы в месяце прогноза к базовому месяцу, среднее по 2019, 2021–2024; ноябрь ×0,985, декабрь ×1,052 | только месяцы ≤ даты данных |

**Почему такая структура.** Посадки маршрута хорошо раскладываются на три независимых множителя: сколько людей возит
маршрут сейчас (уровень), как они распределены по часам и дням недели (форма дня) и как меняется спрос от месяца к месяцу
(сезонность). Модель учит только форму — долю часа от уровня, — поэтому одна модель работает для маршрутов разного размера,
а уровень и сезонность обновляются по свежим данным без переобучения. Та же структура позволяет применять сценарии
(дождь, событие) простым множителем.

**Как считается прогноз на дату.**
1. Уровень маршрута — средние посадки в сутки за последние 56 дней очищенной истории.
2. Форма дня — два набора по 5 моделей CatBoost (разные seed, усреднение): базовый — по календарным признакам, второй —
   плюс длина светового дня в Москве (астрономия; вечерний спрос зависит от темноты). Доли часа двух наборов усредняются
   и смешиваются с профилем последних 4 недель (медиана) (будни 0,6 / 0,4, выходные 0,8 / 0,2, праздничные будни — только CatBoost).
3. Сезонный множитель месяца прогноза относительно базового месяца — среднее отношение за 2019, 2021–2024 по городской
   статистике (только месяцы до даты данных — утечки нет).
4. Прогноз часа = уровень × форма × множитель; маршрут 5 — 0.

**Обучение и проверка.** Гиперпараметры CatBoost и веса смеси подобраны Optuna (148 проб) только на отрезках внутри
обучающих данных (янв–авг); сентябрь–октябрь — итоговая проверка один раз; финальная модель обучена на всех 10 месяцах.
Главные приросты на лидерборде: очистка обучения 0,87950 → 0,88399, ансамбль с длиной светового дня и медианный профиль
0,88399 → 0,88835.

**Горизонты.** День (почасово) и 2 месяца — основная модель (лидерборд). **Год** — та же модель с 12-месячными множителями
(обычный рост уже включён в отношения «месяц через k / базовый»), а форма дня смешивается с формой того же месяца год назад
(доля 0,5; бэктест 0,8575 → 0,8691). Проверка годовой части: город на 12 месяцев — 0,931 / 0,938 / 0,974 (три года),
маршруты по часам на 7–8 месяцев — 0,853–0,862.

**Сверх модели в сервисе:** коридор 80 % (`lo`/`hi`) из распределения ошибок бэктестов по горизонту; поправка −2,5 % в дни
сильного дождя по прогнозу погоды на 16 дней; нормы вагонов (медиана вагонов с валидациями и посадки на вагон по истории)
для рекомендаций выпуска; оценочная разбивка по остановкам (расписание GTFS, пересадочность, жильё и точки притяжения рядом
по OpenStreetMap, время суток, направление).

| Источник | Роль | Как получает сервис | Если недоступен |
|---|---|---|---|

| **Open-Meteo** — прогноз осадков на 16 дней | поправка −2,5 % в дни сильного дождя | скачивает сам | поправка не применяется, прогноз без погоды |
| Telegram Дептранса — ремонты и перекрытия 2025 | подтверждение очистки обучения | офлайн (`external/events_trams_2025.csv`) | в работе не нужен |

Сервис никогда не останавливается из-за внешнего источника: при любой ошибке используется последняя удачная загрузка или
встроенная копия, а в `/model/info` видно, откуда взяты данные. **Утечки нет:** фактические данные ноября–декабря 2025
(посадки, погода, городская статистика) в обучении и сабмите не используются; выгрузка data.mos.ru фильтруется датой данных.

## 4. Область применения модели

| Параметр | Область | Основание |
|---|---|---|
| Маршруты | 9 трамвайных маршрутов обучающих данных: 1, 7, 11, 12, 17, 25, 26, 28, 50; маршрут 5 — всегда 0 (в данных нет посадок) | CatBoost знает маршрут как категорию |
| Детализация | маршрут × дата × час; агрегация по дням, неделям, месяцам и группам маршрутов; по остановкам — только оценка | суммы согласованы |
| Горизонт | от 1 дня до 12 месяцев от даты последних данных | бэктесты до 8 месяцев (маршруты) и 12 месяцев (город) |
| Точность по горизонту (WAPE-score) | 1–2 недели ≈ 0,90 (с еженедельными обновлениями); 2 мес. 0,884 (лидерборд); 3–5 мес. ≈ 0,84–0,86; 8 мес. ≈ 0,89; город на 12 мес. 0,93–0,97 | [TESTS.md](docs/TESTS.md) §1–2, §4д |
| Данные на входе | почасовые успешные валидации, не меньше ~8 недель последней истории (уровень — 56 дней, профиль — 4 недели) | |
| Календарь | Россия (isdayoff.ru) | праздники и переносы — признаки модели |
| Режим работы сети | штатный: история очищается от перекрытий и сбоев, будущие перекрытия модель не знает | учитываются сценарным коэффициентом |

**Вне области применения:** новый маршрут без истории; горизонт больше 12 месяцев (API вернёт понятную ошибку);
внеплановые события (аварии, перекрытия, мероприятия); другие города и виды транспорта без переобучения.
Подробно об ограничениях — [LIMITATIONS_AND_ROADMAP.md](docs/LIMITATIONS_AND_ROADMAP.md).

## 5. Адаптация модели

| Ситуация | Что происходит / что сделать | Где |
|---|---|---|
| Пришли новые валидации | отправить в `POST /ingest/validations` (сырые) или `/ingest/hourly` (почасовые) либо положить CSV в каталог истории — движок пересчитает прогноз сам (≈ 30 с после обнаружения), горизонт сдвинется, прошлая версия уйдёт в архив для контроля точности | `service/api/main.py`, `service/engine/refresher.py` |
| Изменилась трасса, объединили маршруты | уровень и профиль сами перестраиваются по новым данным за 2–8 недель; до этого — сценарный коэффициент | движок, интерфейс |
| Новый год, новые праздники и переносы | ничего: календарь скачивается сам | `service/engine/sources.py` |
| Обновилась городская статистика | ничего: сезонность скачивается сама, только месяцы до даты данных | там же |
| Плановый ремонт, мероприятие, погода | сценарный коэффициент в интерфейсе или параметр `coefficient` — прогноз, рекомендации и план выпуска пересчитываются | интерфейс, API |
| Новый маршрут или прошло полгода | переобучить: `python -m service.engine.train`, пересобрать образ | `service/engine/train.py` |
| Точность упала | виден на экране «Качество прогноза» и алертом (ниже 0,85 за 7 дней) → проверить данные, переобучить | `/monitor/accuracy`, `/alerts` |
| Другой город или вид транспорта | почасовые валидации (8+ недель, лучше год), месячная статистика по виду транспорта за несколько лет, календарь; переобучение и бэктесты | `model/code`, [TESTS.md](docs/TESTS.md) |

## 6. Проверка

**Протокол:** обучение до даты → прогноз на 2 месяца вперёд. Параметры подбирались только на отрезках внутри train;
сентябрь–октябрь — итоговая проверка.

| Период проверки | v4 (без очистки) | v7 (очистка) | **итоговая модель** |
|---|---|---|---|
| Май–июнь | 0,8593 | 0,8722 | 0,8693 |
| Июль–август | 0,8387 | 0,8406 | 0,8414 |
| Сентябрь–октябрь (test) | 0,8545 | 0,8615 | **0,8672** |

| Версия на лидерборде | Что изменено | Скор |
|---|---|---|
| пример организаторов | константы | ≈ 0,48 |
| v3 | CatBoost + профиль + сезонный множитель | 0,87948 |
| v4 | раздельные веса смеси будни / выходные | 0,87950 |
| v5 / v6 | режим ограничений 7 и 50 в ноябре | 0,87802 / 0,87655 |
| v7 | v4 + очистка обучения | 0,88399 |
| v8 | v7 + форма декабря по Google Mobility | 0,88036 |
| **итоговая модель** | **v7 + ансамбль формы дня с длиной светового дня, профиль 4 недели (медиана)** | **0,88835** |

Сервис против сабмита на ноябре–декабре — расхождение 0,0021 % суммы. На реальном октябре 2025 прогноз сервиса,
сделанный до факта: 0,9055 с еженедельными обновлениями, 0,8976 без них. Все прогоны — [docs/TESTS.md](docs/TESTS.md).

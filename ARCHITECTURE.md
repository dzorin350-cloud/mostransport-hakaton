# Архитектура ML-решения: прогноз посадок в трамваях Москвы

**Актуальная версия: v7. Лидерборд: 0,88399 (WAPE-score).** Порог «> 0,88» для максимального балла пройден.

Задача: почасовой прогноз посадок (успешных валидаций) на 10 маршрутах трамвая (1, 5, 7, 11, 12, 17, 25, 26, 28, 50) на 1 ноября – 31 декабря 2025, 14 640 строк. Метрика: WAPE-score = 1 − Σ|y − ŷ| / Σy. Обучающие данные: январь–октябрь 2025.

---

## 1. Идея в одной строке

**Прогноз = уровень маршрута × форма дня × сезонный множитель месяца**, а обучение идёт на данных, очищенных от перекрытий, объединений маршрутов и других разовых сбоев.

## 2. Схема

```
Валидации 2025 (62 млн строк)                     Месячный пассажиропоток трамвая Москвы
        │ успешные, агрегат маршрут × дата × час      (data.mos.ru 62521, 2019 – окт 2025)
        ▼                                                          │
Почасовая сетка (9 маршрутов × 304 дня × 24 ч)                     │
        │                                                          │
        ▼                                                          │
ОЧИСТКА ОБУЧЕНИЯ: аномальные маршруто-дни                          │
(сдвиги доли маршрута в сети > 15%, дни вне ×1,5 от                │
медианы того же типа дня) → заменяются «нормальным» значением      │
        │                                                          │
        ├──► уровень маршрута L: посадок в сутки, последние 56 дней │
        │                                                          │
        ├──► CatBoost: доля от уровня по (маршрут, час, день        │
        │    недели, выходной, праздничный будень, до/после        │
        │    выходных); 5 запусков                                  │
        │                                                          │
        ├──► Профиль: среднее (маршрут × день недели × час)         │
        │    за последние 2 недели                                  │
        ▼                                                          ▼
   Смесь формы дня: будни 0,6·CB + 0,4·профиль;       Сезонный множитель месяца:
   выходные 0,8·CB + 0,2·профиль;                     среднее отношение «месяц / октябрь»
   праздничные будни — только CB                      за 2019, 2021–2024 (2020 исключён)
        │                                                          │
        └──────────────────────────► × ◄───────────────────────────┘
                                     │
                           прогноз маршрут × дата × час
                       (маршрут 5 = 0; 1 ноября = среднее пт и сб)
```

## 3. Компоненты

| Компонент | Что делает | Параметры |
|---|---|---|
| Подготовка | Агрегирует успешные валидации (`validation_result = 1`) в почасовую сетку. Маршрут из `ngpt_route`, время из `tran_date_time`. Пустые часы = 0. Маршрут 5 пуст (одна строка), прогноз для него 0. | duckdb, parquet |
| **Очистка обучения** | 1) Для каждой недели считается доля маршрута в посадках всей сети в будни; отклонение от обычной > 15% — будни недели помечаются. 2) Суточные посадки сравниваются с медианой того же типа дня (будни, суббота, воскресенье) за ±5 недель; отклонение больше чем в 1,5 раза — день помечается. Помеченные маршруто-дни заменяются: медиана того же типа дня по чистым дням × обычная почасовая доля маршрута. Праздники не трогаются. В финальном обучении помечено 168 маршруто-дней (7-й — 42, 50-й — 58, 25-й — 22, 28-й — 14, остальные по 7–11). | порог 1,5; порог недели 15% |
| Календарь | `dow`, `hour`, `off` (выходной или праздник), `hol_wd` (праздничный будень), `pre`/`post` (рабочий день до/после выходных). Проверен по производственному календарю isdayoff.ru: 1 ноября — рабочая суббота, нерабочие 3–4 ноября и 31 декабря. | |
| Уровень маршрута | Среднее посадок в сутки за последние 56 дней очищенных данных. | 56 дней |
| CatBoost | Цель — доля `y / L_norm`, где `L_norm` — скользящее 42-дневное среднее суточного итога маршрута; вес строки — `L_norm`. | RMSE, 800 итераций, глубина 8, lr 0,049, l2 12, Bernoulli 0,59; подобраны Optuna (148 проб) |
| Профиль | Среднее посадок по «маршрут × день недели × час» за последние 2 недели, без праздничных будней. | 2 недели |
| Смесь | Будни 0,6·CB + 0,4·профиль, выходные 0,8·CB + 0,2·профиль, праздничные будни — только CB. | веса подобраны на внутренних периодах |
| Сезонный множитель | Отношение суточного пассажиропотока трамвая Москвы в месяце к октябрю, среднее по 2019, 2021–2024. Ноябрь ×0,985, декабрь ×1,052. Используются только месяцы до октября 2025 включительно. | data.mos.ru, набор 62521 |

## 6. Горизонты прогноза

| Горизонт | Статус | Проверка |
|---|---|---|
| **День** (почасово) | работает | ошибка ниже в первые недели (WAPE 0,09–0,17 против 0,17–0,27 на 6–9 неделях) |
| **Месяц** (61 день) | работает, основная задача | лидерборд 0,88399 |
| **Год** (12 месяцев) | работает с 12-месячными множителями | см. ниже |

**Годовой прогноз.** Та же модель, но множители берутся для всех 12 месяцев вперёд: отношение «месяц через k месяцев / базовый месяц» по городским данным прошлых лет. Отдельный тренд не нужен: эти отношения уже включают обычный рост за k месяцев. Календарь следующего года — isdayoff.ru.

- **Город, 12 месяцев вперёд** (из конца октября, по месячным рядам): 0,931 (ноябрь 2022 – октябрь 2023), 0,938 (2023–2024), **0,974** (ноябрь 2024 – октябрь 2025); лучший из пяти методов (наивный, прошлый год, прошлый год × рост, сезонность за 3 года).
- **Наши маршруты по часам, реальные данные** (обучение до конца февраля, марта, апреля 2025; прогноз до октября): 0,853–0,862 за весь период. По горизонту: 1 мес. 0,868, 3 мес. 0,849, 5 мес. 0,840, 8 мес. 0,885. Без множителей летние месяцы проваливаются до 0,66–0,69.
- **Годовая форма дня (в движке):** распределение по часам смешивается с формой того же месяца год назад (доля 0,5); бэктест на маршрутах 0,8575 → 0,8691. Явный рост вместо зашитого в множители проверен и не внедрён (`docs/TESTS.md` §2).
- **Результат (до годовой формы):** `forecast_year_2025-11_2026-10.csv` — почасовой прогноз на ноябрь 2025 – октябрь 2026 (на ноябре–декабре отличие от v7 0,3%).

**Синтетика.** Подробных данных по маршрутам за 2022–2024 в открытом доступе нет (data.mos.ru, Kaggle, публикации Дептранса). Сгенерирована почасовая история 2022–2024: суточный уровень маршрута × городской месячный индекс, почасовая форма из данных 2025 года, праздники по календарю каждого года. Эффект на обучении: +0,1 пункта на 2-месячном горизонте, +0,17 на 7-месячном — в пределах шума, в модель не включена. Причина: синтетика несёт ту же информацию, что и сезонные множители.

## 7. Что пробовали и не внедрили

| Подход | Результат | Почему нет |
|---|---|---|
| Погода как признак модели (температура, осадки, снег по дням) | ±0,1 пункта | эффект не подтверждён |
| Очистка и климатическая поправка на дождь | +0,08 в среднем, −0,25 на сен–окт | нестабильно |
| Расширенный календарь, школьные каникулы, события | 0 … −0,4 | переобучение на короткой истории |

## 7.1 Веб-сервис

Прогноз v7 обёрнут в REST/HTTP API (FastAPI) и интерактивный дашборд —
подробное описание в [`service/README.md`](service/README.md), здесь
только сводка по критериям ТЗ.

**Архитектура и производительность.** Сервис сам применяет модель: фоновый движок
(`service/engine/`) загружает 5 моделей CatBoost, читает историю валидаций, сам скачивает
календарь (isdayoff.ru) и сезонность (data.mos.ru), строит почасовой прогноз на 12 месяцев
вперёд и пересчитывает его при новых данных; воркеры API держат его в памяти и отдают срезы. Разделение по модулям: приём/агрегация
(`build_grid.py`) → очистка и модель (`clean.py`, `pipe.py`) → готовый
прогноз (`forecast.py`) → API (`service/api/main.py`) → фронтенд
(`service/web/index.html`). Нагрузочный тест (Locust, Docker, 200
пользователей, старый профиль только прогноза): **4 vCPU / 4 ГБ, 4 воркера — ≈ 1 030 RPS при загрузке CPU ~60 %, p95 22 мс;
на насыщении ≈ 1 050–1 280 RPS; 2 vCPU / 2 ГБ — 890 RPS; память ~1 ГБ, swap 0, 0 ошибок** — все прогоны в `docs/TESTS.md` §5.

**Доступ и приём данных.** Прототип авторизации (регистрация и вход, OAuth2 Password Flow, JWT, пользователи в SQLite),
приём новых валидаций через `POST /ingest/validations` и `/ingest/hourly` с автоматическим пересчётом прогноза,
понятные сообщения об ошибках на русском. См. `docs/JURY.md`, `docs/TESTS.md` §4а.

**Полнота функциональности.** Три горизонта (день/месяц/год) через
`/forecast?granularity=hour|day|week|month`; фильтр по маршрутам и часам;
интерактивная карта Москвы (MapLibre, геометрия 9 маршрутов из
OpenStreetMap) с раскраской по загрузке; экспорт в CSV и XLSX
(`/forecast/export?fmt=csv|xlsx`).

**Корректирующие коэффициенты в интерфейсе.** Слайдер `coefficient`
(×0.5…×1.5) и пресеты «Дождь»/«Событие»/«Норма» в дашборде — множитель
применяется поверх готового прогноза без переобучения (мультипликативная
структура модели, §1) и мгновенно виден на карте, графиках и KPI.

**Бизнес-ценность.** Прогноз на уровне маршрут×час даёт диспетчеру ЕДЦ
три прямых применения: (1) перераспределение подвижного состава на
маршруты с растущей сезонной нагрузкой без ожидания жалоб на
переполнение; (2) точка отсчёта для корректировки расписания — модель
явно показывает часы пик (например, 17:00–19:00 в будни) и провалы
(ночные часы, первый день после праздничного блока), на которые
расписание может не быть рассчитано; (3) сценарное планирование через
коэффициенты — «что если пойдёт дождь» или «на маршруте 17 концерт»,
без пересчёта модели. Ограничения понимания: модель не видит будущих
внеплановых перекрытий (§8) и не объясняет причину пиков — только
предсказывает их величину.

## 8. Ограничения
- Главная неопределённость — уровень ноября–декабря: сезонный множитель между годами колеблется до ±5%.
- Будущие перекрытия и ремонты модель не видит, предполагается нормальная работа маршрутов.
- Почасовая форма дня даёт основную часть остаточной ошибки (~9%); её не объяснили ни погода, ни календарь, ни события.
- Модель валидна для 9 маршрутов обучающих данных; для нового маршрута нужен запасной прогноз (средний профиль сети × заданный уровень).

## 9. Файлы и воспроизводимость
- **`v7/`** — замороженная версия: код, данные, отправленный файл с md5. Запуск `cd v7/code && python build_grid.py && python final_v7.py` воспроизводит `submission_v7.csv` байт в байт (проверено).
  - `final_v7.py` — финальный запуск; `clean.py` — очистка; `pipe.py` — CatBoost, профиль, сезонность; `model.py` — данные и календарь; `best_params_final.json` — параметры Optuna; `build_grid.py` — сетка из `labels/`.
- `service/engine/` — движок прогноза в сервисе; `docs/TESTS.md` — все прогоны и тесты; `docs/year_model_and_engine_report.md` — отчёт по годовой модели и движку.
- `ml_scripts/` — все эксперименты (валидация, Optuna, события, погода, синтетика, годовой прогноз).
- `external/` — внешние данные: календари, data.mos.ru, события Дептранса, погода, Google Mobility.
- Сабмиты: `submission_v7.csv` (лучший), остальные `submission_v*.csv` — история.
- **`service/`** — веб-сервис (API + дашборд), Docker Compose: `cd service && docker compose up -d --build`. Подробности — `service/README.md`.

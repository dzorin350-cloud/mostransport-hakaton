# Инструкция для жюри: запуск веб-сервиса, API, проверка

ИИ-прогноз загрузки трамвайных маршрутов Москвы: почасовой прогноз посадок по маршрутам на горизонт от дня до года,
рабочее место диспетчера (оперативная ситуация, рекомендации, план выпуска вагонов, журнал решений, контроль точности),
REST API и экспорт. Итоговая модель — WAPE-score на лидерборде **0,88960**.

## Запуск (≈ 3–5 минут при первой сборке)

Нужны Docker с Docker Compose и доступ в интернет (сервис сам скачивает календарь и сезонность; без интернета работает
на встроенных копиях).

```bash
git clone https://github.com/dzorin350-cloud/mostransport-hakaton.git
cd mostransport-hakaton/service
docker compose up -d --build
```

- **Интерфейс:** http://127.0.0.1:8080 — окно входа, **демо-аккаунт `demo` / `demo2025`** (или вкладка «Регистрация»).
- **API:** http://127.0.0.1:8123, интерактивная документация Swagger — **http://127.0.0.1:8123/docs**.
- Поднимаются три контейнера: `api` (модель, движок прогноза, API), `web` (интерфейс, nginx), `db` (PostgreSQL:
  пользователи, журнал решений, журнал приёма данных). Готовность — `docker compose ps` показывает `api … (healthy)`
  через ~30 с после старта.
- Раздел «Качество прогноза» заполняется через ~2 минуты после старта (в фоне строятся прогнозы для проверки на октябре 2025).
- Конфигурация по умолчанию — 4 vCPU / 4 ГБ; минимальная по ТЗ (2 vCPU / 2 ГБ):
  `docker compose -f docker-compose.yml -f docker-compose.2cpu.yml up -d --build`.
- Остановить: `docker compose down` (с удалением пользователей и принятых данных — `docker compose down -v`).

**Демо-время.** Данные заканчиваются 31.10.2025, поэтому стенд работает в демо-режиме: «сегодня» — 01.11.2025 (первый день
прогноза, период, на котором измерен скор), время суток — текущее московское. В проде — `NOW_MODE=real`.

## Возможности интерфейса (разделы меню слева)

1. **Обзор** — прогноз посадок за период, маршруты с риском, пиковый час, график динамики с **коридором 80 %**, нагрузка по
   маршрутам, состояние маршрутов с выпуском вагонов. Кнопка **«Параметры»**: период (День / Месяц / Год или даты), маршруты,
   часы и **сценарий** (База / Непогода / Мероприятие / Сбой сети или ползунок ×0,6…×1,4) — прогноз и рекомендации
   пересчитываются на сервере.
2. **Оперативная ситуация** — текущий час и 3 следующих по маршрутам; вкладка **«Рекомендации»**: что сделать
   (добавить / снять вагоны, календарь, погода) с кнопками **Принять / Позже / Отклонить**.
3. **Журнал решений** — принятое решение появляется здесь (хранится в PostgreSQL).
4. **Карта и остановки** — карта Москвы с маршрутами (цвет — относительный объём посадок) и оценочными посадками по остановкам.
5. **Загрузка вагонов** — обычный и рекомендуемый выпуск по маршрутам, часы риска переполнения.
6. **План выпуска** — план на 7 дней: маршрут × час, прогноз с коридором, «обычно → рекомендуем», причина; **Экспорт** в CSV / XLSX.
7. **Качество прогноза** — прогноз, сделанный до факта, против факта (реальный октябрь 2025: 0,905).
8. **Экспорт** — кнопка «Экспорт» у каждой таблицы и у прогноза (CSV / XLSX).

Погода на стенде: поправка на сильный дождь (−2,5 %) в демо-режиме взята по фактической погоде архива за 1–16 ноября 2025
(12 и 15 ноября); в проде — прогноз погоды на 16 дней вперёд. В сабмите погода не используется.

## API через curl

```bash
B=http://127.0.0.1:8123
TOKEN=$(curl -s -X POST $B/auth/token -d 'username=demo&password=demo2025' | python3 -c 'import json,sys;print(json.load(sys.stdin)["access_token"])')
H="Authorization: Bearer $TOKEN"

curl -H "$H" "$B/model/info"                                                                  # как построен прогноз, источники данных
curl -H "$H" "$B/forecast?date_from=2025-11-12&date_to=2025-11-12&route=17"                   # день по часам (с коридором lo/hi)
curl -H "$H" "$B/forecast?date_from=2025-11-01&date_to=2025-11-30&granularity=day"            # месяц по дням
curl -H "$H" "$B/forecast?date_from=2025-11-01&date_to=2026-10-31&granularity=month&route=17" # год по месяцам
curl -H "$H" "$B/forecast?date_from=2025-11-10&date_to=2025-11-16&granularity=week&coefficient=0.95"   # сценарий
curl -H "$H" -o forecast.xlsx "$B/forecast/export?date_from=2025-11-01&date_to=2025-11-07&fmt=xlsx"
curl -H "$H" "$B/now"                                                                          # оперативная ситуация (демо-дата, час по Москве)
curl -H "$H" "$B/alerts?date=2025-11-13&hour=8"                                               # рекомендации для диспетчера
curl -H "$H" "$B/plan?date_from=2025-11-13&date_to=2025-11-14"                                # план выпуска
curl -H "$H" -o plan.xlsx "$B/plan/export?date_from=2025-11-13&date_to=2025-11-19"            # план выпуска в XLSX
curl -H "$H" "$B/fleet?date_from=2025-11-13&date_to=2025-11-13&route=17"                      # загрузка вагонов
curl -H "$H" "$B/forecast/stops?date_from=2025-11-12&date_to=2025-11-12&route=17&hour_from=7&hour_to=9"  # по остановкам (оценка)
curl -H "$H" "$B/monitor/accuracy"                                                             # точность прогноза на поступивших фактах
curl -H "$H" "$B/forecast?date_from=2027-01-01&date_to=2027-01-02"                            # вне горизонта → понятная ошибка
```

| Эндпоинт | Назначение |
|---|---|
| `POST /auth/register`, `POST /auth/token`, `GET /auth/me` | регистрация, вход (OAuth2 Password Flow → JWT), текущий пользователь |
| `GET /forecast`, `GET /forecast/export` | прогноз с коридором 80 % (`lo`, `hi`): `date_from`, `date_to`, `route` (несколько), `hour_from`/`hour_to`, `granularity=hour\|day\|week\|month`, `coefficient`; экспорт `fmt=csv\|xlsx` |
| `GET /now`, `GET /alerts` | оперативная ситуация и рекомендации с действием, уверенностью и сроком реакции |
| `GET /fleet`, `GET /plan`, `GET /plan/export` | загрузка вагонов, план выпуска на 1–7 дней, XLSX для депо |
| `POST /decisions`, `GET /decisions`, `GET /decisions/report` | журнал решений диспетчера |
| `GET /monitor/accuracy` | точность прогноза на поступивших фактах (прогноз из архива, сделанный до факта) |
| `POST /ingest/hourly`, `POST /ingest/validations` | приём новых данных (почасовые посадки или сырые валидации в формате `train.csv`) → автоматический пересчёт |
| `GET /stops`, `GET /forecast/stops` | остановки и оценочный прогноз по остановкам |
| `GET /model/info`, `GET /routes`, `GET /routes/geometry` | сведения о модели и данных, маршруты и их геометрия |
| `GET /health`, `GET /ready`, `GET /metrics` | состояние, готовность, счётчики (без авторизации) |

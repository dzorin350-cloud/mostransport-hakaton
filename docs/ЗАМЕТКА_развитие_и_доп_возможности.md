# ЗАМЕТКА (черновик для обсуждения с командой): дополнительные возможности и план развития

> Это заметка, а не финальный текст. Список собран по ходу работы; формулировки и приоритеты обсуждаем командой.

## Реализованные дополнительные возможности (сверх базовых требований)
- **Сервис сам применяет модель и сам скачивает внешние данные** (календарь isdayoff.ru, сезонность data.mos.ru); при недоступности источника — кэш и встроенная копия, статус виден в `/model/info`.
- **Приём новых данных через API** (`/ingest/validations` — сырые валидации, `/ingest/hourly` — агрегаты): прогноз пересчитывается сам, горизонт сдвигается без перезапуска.
- **Горячая перезагрузка прогноза** в воркерах API без простоя.
- **Произвольный диапазон** до 12 месяцев, детализация час / день / неделя / месяц, проверка горизонта.
- **Годовой прогноз** с сезонной формой дня (форма того же месяца год назад, +1,2 пункта на бэктесте).
- **Очистка обучения от аномалий** (перекрытия, объединения маршрутов, отмены по выходным), подтверждённая объявлениями Дептранса.
- **Корректирующие коэффициенты** в интерфейсе; «Дождь» — по измеренному эффекту (×0,96).
- **Прототип авторизации**: регистрация и вход (OAuth2 Password Flow, JWT), пользователи в SQLite.
- **Понятные сообщения об ошибках** на русском (параметры, даты, горизонт, авторизация, приём данных).
- **Метаданные прогноза**: дата данных, версия модели, множители, источники — в ответах API.
- **Воспроизводимость**: финальная модель v7 пересобирается из репозитория байт в байт; все прогоны описаны в `docs/TESTS.md`.
- **Две конфигурации контейнера** по ТЗ (2 и 4 vCPU), число воркеров = числу vCPU.

## План развития после хакатона (черновик)
1. **Остановки и участки.** Разбивка прогноза маршрута по остановкам по GTFS-расписанию (data.mos.ru 60661–60666) и данным телематики (привязка к остановкам через координаты ТС); в перспективе — прогноз загрузки по перегонам.
2. **Потоковый приём.** Валидации и телематика напрямую из очереди (Kafka / NATS) вместо HTTP-загрузок; хранилище истории — ClickHouse.
3. **Погода по прогнозу.** Поправка на ближайшие 1–14 дней по прогнозу погоды (Яндекс Погода по договору, Open-Meteo); после накопления истории — признак модели.
4. **Плановые события.** Автоматический разбор объявлений Дептранса (ремонты, перекрытия, мероприятия) → сценарии в прогнозе на будущие даты.
5. **Регулярное переобучение** CatBoost по расписанию с проверкой качества на отложенном периоде перед выкладкой; реестр моделей (MLflow).
6. **Коридор неопределённости** (квантильные модели или бэктест-ошибки по горизонту) — показывать диспетчеру диапазон, а не одно число.
7. **Маршрутная сезонность** после накопления года истории по каждому маршруту.
8. **Диспетчерские сценарии:** рекомендации по выпуску подвижного состава (вагонов на маршрут по часам) из прогноза и вместимости.
9. **Промышленная авторизация:** ЕСИА / корпоративный SSO (OAuth2 / OIDC), роли (диспетчер, аналитик, администратор), аудит.
10. **Перенос на Java-стек** при требовании заказчика: инференс CatBoost через ONNX Runtime в Spring WebFlux (модели экспортируются в ONNX).

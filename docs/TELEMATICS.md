# Телематика и привязка к остановкам

## Что такое телематика
Телематика — поток навигационных данных с бортовых терминалов транспорта: каждые несколько секунд терминал вагона передаёт
идентификатор ТС, время, координаты (GPS/ГЛОНАСС), скорость, курс. В России такие терминалы работают по протоколам
**NDTP** (Navigation Data Transfer Protocol, стек NPL/NPH — описан в нормативных документах, см.
[КонсультантПлюс](https://www.consultant.ru/document/cons_doc_LAW_134189/bdcce30e3dae113b4904e5d13bc543395e4eda31/))
и EGTS. По уточнению организаторов, в пакетах NDTP (ячейка `G6CellNav00`) есть `unitId`, координаты, скорость и курс,
но нет остановки — привязку к остановке (map matching) делает команда.

## Зачем она нужна
В валидациях нет остановки: есть время, валидатор (`device_no`), вагон (`garage_number`), выход (`bus_exit_no`).
Если есть координаты того же вагона по времени, каждую валидацию можно привязать к месту, где стоял вагон:

```
валидация (garage_number, tran_date_time) → позиция вагона в этот момент (телематика) → ближайшая остановка маршрута (GTFS)
```

Так получается **фактический** пассажиропоток по остановкам, и модель можно учить прогнозировать его напрямую
(сейчас разбивка по остановкам — оценочная, по весам).

**Вывод:** открытых исторических данных телематики за 2025 год нет.

## Что можно сделать
1. **Запросить у организаторов** телеметрию или эмулятор NDTP (упоминается в их уточнениях). Если он появится:
   приём пакетов NDTP → позиции вагонов → сопоставление валидаций по `garage_number` и времени → ближайшая остановка
   маршрута по GTFS → почасовые посадки по остановкам → обучение модели на уровне остановки. Приёмник данных в сервисе
   (`POST /ingest/*`) для этого расширяется.
2. **Собирать положение ТС в реальном времени** из открытых источников с сегодняшнего дня — для истории 2025 года не поможет,
   и нужно проверить условия использования.
3. **Сейчас:** оценочная разбивка по расписанию GTFS (`service/engine/build_stops.py`, API `/stops`, `/forecast/stops`).

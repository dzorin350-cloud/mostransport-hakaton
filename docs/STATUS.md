## Жёсткая оценка текущего решения

**Сильное.** Модель — лучшая часть решения: WAPE-score 0,88399 (верхняя корзина, максимум баллов по критерию 1), честная валидация,
воспроизводимость байт в байт, подтверждённые внешние источники. Сервис рабочий: сам применяет модель, сам скачивает данные, принимает
новые данные через API, держит ~1 000 RPS при CPU ~60 %, есть авторизация, экспорт, понятные ошибки, подробная документация.

**Слабое — честно:**
1. **Потоковая часть — закрыта в бэкенде.** Телеметрия и эмулятор NDTP относятся к другой задаче (отклонения от графика), не к нашей.
   Для прогноза загрузки поток = поступающие факты и сравнение с ML-прогнозом: приём через API, автоматический пересчёт, архив версий
   прогноза, `/monitor/accuracy`. Проверено на реальном октябре: WAPE-score 0,9038 с еженедельными обновлениями (0,8952 без них).
   Остаётся: экран «качество прогноза» во фронтенде.
2. **Продукт для диспетчера — бэкенд готов, фронтенд нет.** `/fleet`: загрузка вагонов (норма / повышенная / риск переполнения)
   и рекомендация выпуска; проверено на сен–окт: рекомендация совпадает с потребностью по фактическому спросу (пик 676 против 674
   вагоно-часов), перенос ~160 вагоно-часов в день из межпика в пик. Риск переполнения — полнота 0,63, точность 0,45 (умеренно).
   В интерфейсе этого пока нет.
3. **Интерфейс заметно слабее модели.** Один HTML-файл (не React), остановок на карте нет, карта статична (нет динамики по часам),
   KPI задержки зашит в разметку. Жюри видит продукт через интерфейс — здесь мы проигрываем командам с хорошим фронтендом.
4. **Остановки — эвристика.** Разбивка по остановкам не выучена на данных (их нет), коэффициенты экспертные. Честно подписано,
   но при вопросе «насколько это точно?» ответа нет.
5. **Коридор неопределённости — есть** (`lo`/`hi` в `/forecast`, 80 %, покрытие на отложенном периоде: часы 78–83 %, дни 82–89 %);
   для недель и месяцев калибровочных точек мало. В интерфейсе не показан.
6. **Трение при проверке — частично снято.** Демо-аккаунт `demo` / `demo2025`; готовые образы amd64 и arm64 (≈ 330 МБ, файлы, не в реестре);
   репозиторий по-прежнему приватный; часть документов — неутверждённые заметки.
7. **Риски вопросов на защите:** файл data.mos.ru 62521 содержал ноябрь–декабрь 2025 (отфильтрован, метод от них не зависит — рассказать первыми);
   8 сабмитов на лидерборде (правила разрешают); замеры нагрузки на ноутбуке без вентилятора (с оговоркой про троттлинг).

**Итог:** технически ≈ 28–29 из 29 баллов по нашей оценке, но это оценка по формальным пунктам. Победа решится питчем (10 баллов),
закрытием потоковой части и тем, выглядит ли решение инструментом диспетчера. Сейчас это сильная модель в аккуратной обвязке, а не продукт.
Повышать WAPE-score дальше бессмысленно — баллов не прибавится.

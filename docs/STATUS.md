## Главная мысль

Модель — на максимуме баллов (WAPE-score 0,88399), повышать скор дальше бессмысленно. Победа решится тем, **закрывает ли решение
боль диспетчера**: сейчас почти вся диспетчерская логика есть в API, но не доведена до готовых решений («что сделать, когда, сколько
вагонов») и не показана в интерфейсе. Весь оставшийся план подчинён этому.

## Что уже готово

- **Модель v7:** WAPE-score 0,88399 (верхняя корзина), честная валидация, воспроизводимость байт в байт.
- **Движок:** сам применяет модель и скачивает внешние данные (календарь, сезонность, погода), принимает новые факты через API
  и сам пересчитывает прогноз; архив версий прогноза; `/monitor/accuracy` — факт против прогноза (реальный октябрь: 0,9038 с еженедельными
  обновлениями против 0,8952 без них).
- **Для диспетчера (API):** загрузка вагонов и рекомендация выпуска `/fleet`, коридор 80 % (`lo`/`hi`), режим «Сейчас» с демо-временем
  `/now`, алерты `/alerts`, подсказки, оценочная разбивка по остановкам `/stops`, `/forecast/stops`.
- **Погода:** поправка в дни сильного дождя по прогнозу на 16 дней; на стенде демо по архиву.
- **Доступ и эксплуатация:** авторизация (OAuth2 + JWT), демо-аккаунт `demo` / `demo2025`, ошибки на русском, образы amd64 и arm64 (файлы).
- **Производительность:** ≈ 995 RPS при CPU ~75 %, p95 40 мс, RAM ≈ 830 МБ, swap 0 (4 vCPU, с коридором).
- **Документация:** для жюри, тесты, внешние данные, область применимости, спецификация для фронтенда.

## Боль диспетчера → что есть → чего не хватает

| Боль диспетчера | Что есть | Чего не хватает |
|---|---|---|
| **Узнаёт о давке по факту и по жалобам, а не заранее** | прогноз маршрут × час, статус загрузки, `/alerts` | алерт говорит «риск», но не говорит **что сделать**: «маршрут 17, 7–9 ч: +6 вагонов» |
| **Выпуск вагонов — по нормативу и опыту** | `/fleet`: рекомендация по часам; на сен–окт совпала с потребностью по факту (пик 676 против 674 вагоно-часов) | нет **плана выпуска** на завтра / неделю, который можно отдать в депо и выгрузить в Excel |
| **Пустые вагоны в межпик** | рекомендация «снять»: перенос ≈ 160 вагоно-часов в день из межпика в пик | эффект не посчитан в понятных цифрах: сколько часов переполнения убрано без новых вагонов |
| **Нетипичные дни** (переносы праздников, рабочие субботы, дождь, ремонты) | календарь isdayoff, дождь по прогнозу, очистка ремонтов, будничные нормы в рабочую субботу | сценарий «что если» (дождь, событие, перекрытие) меняет только прогноз — план выпуска и алерты не пересчитываются |
| **Можно ли верить цифре** | коридор 80 %, `/monitor/accuracy` | диспетчер этого не видит: нет «уверенности» в алерте и разбора «где ошиблись вчера» |
| **Где на маршруте давка** | оценочная разбивка по остановкам и направлениям | точность не проверяема — подписывать как оценку |
| **Никто не проверяет, помогли ли рекомендации** | — | нет журнала «принял / отклонил / почему» и отчёта по нему |

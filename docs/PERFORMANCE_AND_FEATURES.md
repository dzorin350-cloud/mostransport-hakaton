# Производительность и дополнительные возможности

## 1. Производительность

**Итог:** на конфигурации ТЗ (4 vCPU / 4 ГБ, 4 воркера, PostgreSQL) сервис при обычном трафике 200–400 RPS отвечает
с **p95 6 мс** при загрузке CPU 11–17 %; требование **p95 ≤ 300 мс выдерживается до ≈ 1 150–1 250 RPS**, потолок
пропускной способности ≈ 1 320 RPS; **0 ошибок** из ≈ 600 тыс. запросов, память ≈ 1,1 ГБ, swap 0.

**Как мерили.** Locust, смешанный профиль работы диспетчера ([`service/api/loadtest_dispatcher.py`](../service/api/loadtest_dispatcher.py)):
почасовой прогноз (вес 8), оперативная ситуация (3), рекомендации (2), план выпуска (2), остановки (2), качество прогноза (1),
выгрузка плана в XLSX (1); каждый виртуальный пользователь входит с токеном и делает ≈ 2 запроса/с. Ступени по 75 с,
статистика после набора пользователей; CPU и память — `docker stats` контейнера API. Стенд: Apple M5, Docker Desktop,
Locust на той же машине. Дата замера — 27.09.2026, версия `main` 0d8036a.

| Время пересчёта прогноза (12 месяцев, 9 маршрутов) | ≈ 25 с |
| Память контейнера API | ≈ 0,9–1,1 ГБ из 4 ГБ (5 моделей CatBoost + прогноз на 12 месяцев в каждом воркере), swap 0 |

**Почему быстро.** Модель не запускается на каждый запрос: движок пересчитывает прогноз только при новых данных, воркеры API
держат готовую таблицу в памяти и берут срез по дате двоичным поиском; ответы плана, рекомендаций, остановок и XLSX
кэшируются по версии прогноза и параметрам. Число воркеров = числу vCPU.

**Известное ограничение.** Во время пересчёта прогноза (≈ 4–5 с счётной части) движок занимает все ядра контейнера, и p95
на это время поднимается до ≈ 1,4 с (ошибок нет). План исправления — в [LIMITATIONS_AND_ROADMAP.md](LIMITATIONS_AND_ROADMAP.md).

**Оговорки.** Профиль повторяет одни и те же параметры, поэтому многие ответы берутся из кэша; при более разнообразных
запросах предел ниже. Locust на той же машине и ноутбук без активного охлаждения занижают результат.

Сырые результаты и повтор: [`service/api/loadtest_report/steps_4cpu_main_0d8036a/`](../service/api/loadtest_report/steps_4cpu_main_0d8036a/),
скрипт [`service/api/loadtest_steps.sh`](../service/api/loadtest_steps.sh); все прогоны — [TESTS.md](TESTS.md) §5.

## 2. Реализованные дополнительные возможности

Сверх базовых требований (прогноз маршрут × час, API, дашборд с картой, экспорт).

### Для диспетчера
| Возможность | Что делает | Проверка |
|---|---|---|
| **Оперативная ситуация** (`/now`) | текущий час и 3 следующих по каждому маршруту: прогноз, коридор, загрузка вагонов, выпуск | — |
| **Рекомендации с действием** (`/alerts`) | «Маршрут 17, 7–9 ч: добавить до 6 вагонов к 7:00», «можно снять 5 вагонов», праздники и переносы, сильный дождь, падение точности, устаревшие данные; уровень, уверенность, срок реакции, число пассажиров под риском | риск переполнения на сен–окт: полнота 0,63, точность 0,45 |
| **Журнал решений** (`/decisions`) | принять / отложить / отклонить рекомендацию с комментарием; отчёт с фактом посадок; хранится в PostgreSQL | — |
| **Загрузка вагонов** (`/fleet`) | посадки на вагон относительно истории маршрута: норма / повышенная / риск переполнения; рекомендуемый выпуск (не меньше 60 % обычного) | на сен–окт рекомендация совпала с потребностью по факту: пик 676 против 674 вагоно-часов; перенос ≈ 160 вагоно-часов в день из межпика в пик |
| **План выпуска** (`/plan`, XLSX) | маршрут × час на 1–7 дней: прогноз с коридором, «обычно → рекомендуем», причина (пик, праздник, дождь, сценарий), итог в вагоно-часах; в праздники — по воскресным нормам | — |
| **Сценарии «что если»** | коэффициент (База / Непогода / Мероприятие / Сбой сети или ×0,6…×1,4) пересчитывает прогноз, загрузку, рекомендации и план | — |

### Прогноз и доверие к нему
| Возможность | Что делает | Проверка |
|---|---|---|
| **Коридор 80 %** (`lo`/`hi`) | диапазон, в который факт попадает в 8 из 10 случаев, шире на дальнем горизонте | покрытие на отложенном периоде: часы 78–83 %, дни 82–89 % |
| **Контроль точности** (`/monitor/accuracy`, экран «Качество прогноза») | каждый день факта сравнивается с прогнозом, сделанным до него (архив версий) | реальный октябрь 2025: 0,9038 с еженедельными обновлениями, 0,8952 без них |
| **Горизонты от часа до года** | детализация час / день / неделя / месяц на 12 месяцев вперёд; годовая форма дня | бэктесты до 12 месяцев |
| **Поправка на сильный дождь** | −2,5 % в дни с осадками в 3+ дневных сроках по прогнозу погоды на 16 дней | +0,65 пункта на таких днях в бэктесте |
| **Очистка обучения от аномалий** | перекрытия, объединения маршрутов, сбои не портят модель; совпадают с объявлениями Дептранса | 0,87950 → 0,88399 на лидерборде |
| **Оценка по остановкам** (`/forecast/stops`, карта) | разбивка прогноза маршрута по 449 остановкам: расписание GTFS, пересадочность, жильё и точки притяжения рядом (OpenStreetMap), время суток, направление | оценка, точность проверить нельзя (нет данных по остановкам) |

### Эксплуатация
| Возможность | Что делает |
|---|---|
| **Сервис сам применяет модель и сам скачивает внешние данные** | календарь, сезонность, погода; при недоступности — кэш и встроенная копия, статус в `/model/info` |
| **Приём новых данных через API** | сырые валидации или почасовые посадки; проверка формата, защита от повторов и конфликтов; автоматический пересчёт |
| **Неизменяемые версии прогноза** | атомарная публикация, горячая подмена в воркерах без простоя, архив для контроля точности |
| **Самовосстановление** | падение фонового движка или API → перезапуск контейнера, прогноз сохраняется на томе |
| **Авторизация** | регистрация и вход (OAuth2 Password Flow, JWT), пароли PBKDF2, демо-аккаунт для жюри |
| **Понятные ошибки на русском** | неверные даты, вне горизонта, авторизация, формат данных |
| **Две конфигурации по ТЗ** | 4 vCPU / 4 ГБ и 2 vCPU / 2 ГБ, число воркеров = числу vCPU |
| **Воспроизводимость** | сабмит пересобирается из репозитория байт в байт, в том числе в Docker; тесты API (`service/api/tests/`) |

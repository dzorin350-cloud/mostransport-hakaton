# Производительность и дополнительные возможности

## 1. Производительность

**Итог (4 vCPU / 4 ГБ, 4 воркера, PostgreSQL):** при обычном трафике 200–400 RPS — **p95 6 мс**, CPU 11–17 %;
требование **p95 ≤ 300 мс выдерживается до ≈ 1 100–1 250 RPS**, потолок ≈ 1 100–1 320 RPS (два прогона); **0 ошибок**
из ≈ 1,2 млн запросов, память ≈ 1,1 ГБ, swap 0.

**Как мерили:** Locust, смешанный профиль диспетчера ([`loadtest_dispatcher.py`](../service/api/loadtest_dispatcher.py)):
прогноз, оперативная ситуация, рекомендации, план выпуска, остановки, качество, выгрузка XLSX; вход с токеном, ≈ 2 запроса/с
на пользователя; ступени по 75 с; CPU и память — `docker stats`. Apple M5, Locust на той же машине, 27.09.2026.
Прогон на итоговой модели (второй столбец RPS / p95 — прогон на предыдущей версии модели). Модель на запрос не запускается,
поэтому версия модели на обработку запросов не влияет; разница на насыщении — нагрев ноутбука без вентилятора.

| 4 vCPU, 210 пользователей, 10 минут | 395 RPS, p95 72 мс, ≈ 236 тыс. запросов, 0 ошибок, память стабильна |
| Приём данных под нагрузкой | ответ 22–95 мс, новая версия прогноза через 7–36 с, 0 ошибок |
| Отказ фонового движка под нагрузкой | перезапуск, `/ready` через 3–6 с с той же версией прогноза |
| Пересчёт прогноза на 12 месяцев | ≈ 25 с |

**Почему быстро:** модель не запускается на каждый запрос — прогноз пересчитывается при новых данных, воркеры держат
его в памяти и берут срез двоичным поиском; ответы плана, рекомендаций, остановок и XLSX кэшируются по версии прогноза.

**Ограничения замера:** во время пересчёта (4–5 с) p95 растёт до ≈ 1,4 с; повтор на итоговой модели с одновременной
загрузкой фактов дал p95 991 мс за всю 13-секундную фазу (100 пользователей, 0 ошибок из 26 963 запросов,
подробности в [`TESTS.md`](TESTS.md) §5). Профиль повторяет параметры (много попаданий
в кэш); Locust на той же машине. Сырые результаты — [`loadtest_report/steps_4cpu_final_C1/`](../service/api/loadtest_report/steps_4cpu_final_C1/) (итоговая модель)
и [`loadtest_report/steps_4cpu_main_0d8036a/`](../service/api/loadtest_report/steps_4cpu_main_0d8036a/) (прошлый прогон),
повтор — [`loadtest_steps.sh`](../service/api/loadtest_steps.sh), все прогоны — [TESTS.md](TESTS.md) §5.

## 2. Дополнительные возможности

| Возможность | Что делает | Проверка |
|---|---|---|
| **Рекомендации с действием** (`/alerts`) | «добавить до 6 вагонов к 7:00», «можно снять 5», праздники, сильный дождь, падение точности, устаревшие данные; уверенность, срок реакции, пассажиры под риском | риск переполнения на сен–окт: полнота 0,63, точность 0,45 |
| **Оперативная ситуация** (`/now`) | текущий и 3 следующих часа по маршрутам: прогноз, коридор, загрузка, выпуск | — |
| **Журнал решений** (`/decisions`) | принять / отложить / отклонить с комментарием, отчёт с фактом; PostgreSQL | — |
| **Загрузка вагонов и план выпуска** (`/fleet`, `/plan`, XLSX) | норма / повышенная / риск; рекомендуемый выпуск (≥ 60 % обычного); план маршрут × час на 7 дней с причиной; в праздники — воскресные нормы | на сен–окт совпало с потребностью: пик 676 против 674 вагоно-часов; перенос ≈ 160 вагоно-часов в день в пик |
| **Сценарии «что если»** | коэффициент пересчитывает прогноз, рекомендации и план | — |
| **Коридор 80 %** | диапазон, где факт в 8 из 10 случаев | покрытие: часы 78–83 %, дни 82–89 % |
| **Контроль точности** (`/monitor/accuracy`) | день факта против прогноза, сделанного до него | реальный октябрь: 0,9052 с еженедельными обновлениями, 0,8968 без |
| **Горизонт от часа до года** | час / день / неделя / месяц на 12 месяцев, годовая форма дня | бэктесты до 12 месяцев |
| **Поправка на сильный дождь** | −2,5 % по прогнозу осадков на 16 дней | +0,65 пункта на таких днях |
| **Очистка обучения** | перекрытия и сбои не портят модель | лидерборд 0,87950 → 0,88399 |
| **Длина светового дня в форме дня** | второй набор моделей CatBoost с астрономической длиной дня: осенью и зимой вечерний спрос сдвигается с темнотой | сен–окт 0,8615 → 0,8672; лидерборд 0,88399 → 0,88835 |
| **Сезонность маршрута** | городской сезонный множитель корректируется на чувствительность маршрута (β по месяцам 2025, сжатие 0,5) | все проверяемые периоды лучше, сен–окт 0,8672 → 0,8776; лидерборд 0,88835 → 0,88960 |
| **Оценка по 449 остановкам** | GTFS, пересадки, жильё и точки притяжения (OSM), время суток, направление | оценка: данных по остановкам нет |
| **Эксплуатация** | сервис сам применяет модель и скачивает внешние данные (источник → кэш → встроенная копия); приём данных через API с защитой от повторов; неизменяемые версии прогноза с горячей подменой; самовосстановление; OAuth2 + JWT, демо-аккаунт; ошибки на русском; конфигурации 2 и 4 vCPU; сабмит воспроизводится байт в байт; тесты API | — |

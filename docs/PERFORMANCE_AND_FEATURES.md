# Производительность и дополнительные возможности

## 1. Производительность

**Коротко.** На конфигурации ТЗ (4 vCPU / 4 ГБ, PostgreSQL) при обычном трафике 200–400 запросов в секунду сервис
отвечает за **5 мс** (p95) и загружает процессор на 10–15 %. Требование p95 ≤ 300 мс выдерживается **до 1 100–1 430
запросов в секунду**. Ошибок нет, память около 1,2 ГБ, swap не используется.

**Как мерили.** Locust имитирует работу диспетчеров: прогноз, оперативная ситуация, рекомендации, план выпуска,
остановки, качество прогноза, выгрузка в Excel. Каждый пользователь входит с токеном и делает около двух запросов
в секунду. Нагрузка растёт ступенями по 75 секунд. Сценарий — [`loadtest_dispatcher.py`](../service/api/loadtest_dispatcher.py),
запуск — [`loadtest_steps.sh`](../service/api/loadtest_steps.sh).

Итоговая модель, 27.09.2026 (Apple M5, Locust на той же машине):

| Пользователей | Запросов/с | p95 | p99 | Ошибки | CPU (от 4 vCPU) | Память |
|---:|---:|---:|---:|---:|---:|---:|
| 100 | 199 | 5 мс | 8 мс | 0 | 10 % | 1,1 ГБ |
| 200 | 397 | 5 мс | 13 мс | 0 | 15 % | 1,1 ГБ |
| 400 | 793 | 5 мс | 49 мс | 0 | 26 % | 1,2 ГБ |
| 600 | 1 167 | 8 мс | 0,8 с | 0 | 40 % | 1,2 ГБ |
| **800** | **1 427** | **170 мс** | 1,7 с | 0 | 85 % | 1,2 ГБ |
| 1 000 | 1 274 | 490 мс | 3,0 с | 0 | 93 % | 1,2 ГБ |

| Другие замеры | Результат |
|---|---|
| 2 vCPU / 2 ГБ, 100 пользователей | 174 запроса/с, p95 110 мс, 0 ошибок |
| 10 минут под нагрузкой, 210 пользователей | 395 запросов/с, p95 72 мс, 236 тыс. запросов без ошибок, память стабильна |
| Приём новых данных под нагрузкой | ответ за 22–95 мс, новый прогноз через 7–36 с, 0 ошибок |
| Падение фонового движка под нагрузкой | контейнер перезапускается, сервис снова готов через 3–6 с |

**Почему быстро.** Модель не запускается на каждый запрос. Прогноз считается один раз при поступлении данных (около
25 секунд), API держит его в памяти, а ответы плана, рекомендаций и выгрузок кэширует.

**Оговорки.** Во время пересчёта прогноза задержка на несколько секунд растёт: p95 до 1–1,4 с, ошибок нет
([подробно](TESTS.md)). Тестовый профиль часто повторяет одни и те же запросы, поэтому на разнообразных запросах предел
будет ниже. Ноутбук без вентилятора нагревается: в трёх прогонах предел колебался от 1 100 до 1 430 запросов в секунду.
Сырые результаты — [`steps_4cpu_final_E1/`](../service/api/loadtest_report/steps_4cpu_final_E1/),
прошлые прогоны — [`steps_4cpu_final_C1/`](../service/api/loadtest_report/steps_4cpu_final_C1/)
и [архив](../reports/archive/loadtest_legacy_20260927.zip).

## 2. Дополнительные возможности

**Для диспетчера**

| Возможность | Что даёт |
|---|---|
| Рекомендации с действием | «добавить 6 вагонов к 7:00», «можно снять 5 вагонов», предупреждения о праздниках и сильном дожде — с уверенностью и сроком реакции |
| Журнал решений | принять, отложить или отклонить рекомендацию; отчёт сравнивает решения с фактом |
| Загрузка вагонов и план выпуска | сколько вагонов выпустить по часам на 7 дней вперёд и почему; на сентябре–октябре рекомендация совпала с реальной потребностью (676 против 674 вагоно-часов в пик) |
| Сценарии «что если» | коэффициент на дождь, мероприятие или сбой пересчитывает прогноз, рекомендации и план |
| Оценка по остановкам | разбивка прогноза маршрута по 449 остановкам по расписанию и окружению; это оценка, данных по остановкам нет |

**Для доверия к прогнозу**

| Возможность | Что даёт |
|---|---|
| Коридор прогноза | диапазон, в который факт попадает в 8 случаях из 10 (проверено: 78–89 %) |
| Контроль точности | каждый день факта сравнивается с прогнозом, сделанным до него; на реальном октябре — 0,908 |
| Горизонт от часа до года | прогноз по часам, дням, неделям и месяцам на 12 месяцев вперёд |
| Поправка на сильный дождь | −2,5 % в дни с сильным дождём по прогнозу погоды на 16 дней |

**Для эксплуатации**

- Сервис сам применяет модель и скачивает внешние данные; при недоступности источника работает на кэше.
- Новые данные принимаются через API, прогноз пересчитывается сам, без простоя.
- После сбоя контейнер перезапускается, прогноз сохраняется.
- Вход по логину и паролю, демо-аккаунт для жюри, понятные ошибки на русском.
- Две конфигурации по ТЗ: 2 и 4 vCPU.
- Сабмит воспроизводится из репозитория байт в байт, API покрыт тестами.

Что дала каждая часть модели для точности — [MODEL.md](MODEL.md).

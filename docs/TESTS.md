## 4б. Оценочная разбивка по остановкам
GTFS data.mos.ru (срез 2026): 9 маршрутов, 449 остановок, 586 остановок-направлений, у всех есть координаты; основной вариант рейса
каждого направления. Окружение каждой остановки — OpenStreetMap (Overpass API): жилые дома и точки притяжения (офисы, вузы, школы,
больницы, ТЦ) в радиусе 400 м; получено для всех 449 остановок (`service/engine/osm_context.py` → `artifacts/osm_stop_context.csv`).
Доли остановок отдельно для утра (5–9), дня (10–15), вечера (16–20) и ночи: утром больше вес у жилых кварталов и у направления в центр
(≈ 61 % посадок маршрута), вечером — у точек притяжения и пересадок, направление из центра (≈ 61 %). Формулы — `service/engine/build_stops.py`.

**Проверить точность нельзя:** пассажиропотока по остановкам нет ни в данных, ни в открытых источниках (см. [TELEMATICS.md](TELEMATICS.md)).
Проверено: сумма по остановкам = прогнозу маршрута в любой период (13.11.2025, маршрут 17: 7–10 ч 12 969,8 → 12 969,6; 17–20 ч 12 690,6 → 12 690,6;
весь день, все маршруты 241 950,7 → 241 950,8), скор на уровне маршрута не меняется. Пример, маршрут 17, 13.11.2025:
утром в топе «Метро Бабушкинская», «Улица Цандера» (жилой квартал), «Метро ВДНХ»; вечером — «Метро ВДНХ», «Метро Бабушкинская», «МЦК Ростокино».
API: `/stops` (GeoJSON), `/forecast/stops`.

## 4в. Загрузка вагонов и рекомендация выпуска
Вагоны в работе — число разных вагонов (`garage_number`) с валидациями на маршруте в этот час; посадок на вагон в час = посадки / вагоны.
Проверка: нормы только по данным до 31.08, прогноз v7 на сен–окт, сравнение с фактом (8 657 маршруто-часов 6–21 ч). Скрипты: `experiments/fleet/`.

| Вариант | Результат |
|---|---|
| Прогнозная против фактической загрузки вагона | корреляция 0,77 |
| «Риск переполнения» (выше 90-го процентиля загрузки маршрута за всю историю) | по факту 13,6 % часов; прогноз находит 63 % (полнота), точность 45 % |
| Первая версия (порог по последним 8 неделям — лето) | отброшена: осенью в «риск» попадала треть часов |

Рекомендация «минимум вагонов, чтобы загрузка не превышала 75-й процентиль маршрута», будни, вагоно-часы в день:

| | Фактический выпуск | Рекомендовано | Нужно по фактическому спросу |
|---|---|---|---|
| Пик 7–8, 17–18 ч | 576 | 676 (+17 %) | 674 |
| Межпик 10–14, 20–21 ч | 897 | 734 (−18 %) | 702 |
| Весь день 6–21 ч | 2 157 | 2 022 (−6 %) | 1 967 |

Рекомендация совпадает с потребностью по фактическому спросу с точностью ±1 вагон в 60 % часов (средняя ошибка 1,5 вагона).
В сервисе добавлено ограничение «не меньше 60 % обычного выпуска» (параметр `min_share`), чтобы не растягивать интервалы вечером.
**Ограничения:** посадки — не наполненность салона (выходов в данных нет), поэтому загрузка относительная (к истории маршрута);
вагоны оцениваются по валидациям; смены, депо и графики выпуска не учитываются.

## 4д. Потоковый контур: факт против ML-прогноза (реальный октябрь 2025)
Сценарий «как в проде»: сервис стартует с историей до 30.09.2025; фактические посадки октября поступают через `POST /ingest/hourly`
порциями (1–7, 8–14, 15–21, 22–31 октября); после каждой порции движок сам пересчитывает прогноз и кладёт версию в архив;
`GET /monitor/accuracy` сравнивает каждый день с прогнозом из архива, сделанным **до** поступления этого дня. Скрипт: `experiments/stream_test_october.sh`.

| Прогноз | WAPE-score (октябрь, 5 781 маршруто-час) | В среднем за, дней до факта |
|---|---|---|
| Самый ранний (от 30.09, без обновлений) | 0,8952 | 16 |
| **Самый свежий до факта (еженедельные обновления)** | **0,9038** | 4,5 |

По маршрутам (самый свежий): 17 — 0,938; 12 — 0,927; 1 — 0,913; 11 — 0,909; 26 — 0,908; 7 — 0,889; 28 — 0,875; 25 — 0,843; 50 — 0,816.
После каждой порции: данные до 07.10 / 14.10 / 21.10 / 31.10, пересчёт без ошибок.

**Найдена и исправлена ошибка:** при данных до середины месяца движок брал городскую статистику за весь текущий месяц — в неё попадали
дни, которых у модели ещё нет (утечка), и пересчёт падал на множителе текущего месяца. Теперь городская статистика и база множителей —
последний полный месяц (при данных до 07.10 — сентябрь). На ноябрь–декабрь (данные до 31.10, полный месяц) не влияет: сверка с v7 — 0,0022 %.

## 4е. Режим «Сейчас», демо-время, алерты
Демо-время: `NOW_MODE=demo`, дата — первый день прогноза (01.11.2025) или параметр `date`, час — пользователя.

| Сценарий | Результат |
|---|---|

| `/alerts?hour=8` (01.11) | перенос сегодня, избыток вагонов утром на 7 маршрутах, праздники 03.11 и 04.11 впереди |
| `/alerts?hour=10&date=2025-11-12` | повышенная загрузка в обед на 5 маршрутах, сильный дождь сегодня (демо), «данные на 12 дн. старше — коридор шире» |

| Время ответа | `/now` ≈ 12 мс, `/alerts` ≈ 45 мс, `/fleet` ≈ 7 мс, `/forecast` ≈ 3 мс |

**Найдено и исправлено:** в день переноса (рабочая суббота) нормы выпуска брались субботние — спрос будний, вагонов «мало», отсюда ложные
«риски переполнения» на 5 маршрутах. Теперь рабочие выходные считаются по будничным нормам. Часы в тексте алертов перечисляются точно
(«8:00–10:00, 11:00–12:00» вместо общего диапазона).

# ИИ-прогноз загрузки трамвайных маршрутов Москвы

Хакатон МТТЕХ. Почасовой прогноз посадок по 10 маршрутам трамвая на горизонт от дня до года и рабочее место диспетчера:
где и когда ждать давки, сколько вагонов выпустить, что делать сейчас.

Итоговая модель — **WAPE-score 0,89136** на лидерборде (ноябрь–декабрь 2025). Как она устроена — [ARCHITECTURE.md](ARCHITECTURE.md).

## Запуск

Нужен Docker с Docker Compose. Интернет желателен: без него сервис работает на встроенных копиях внешних данных.

```bash
git clone https://github.com/dzorin350-cloud/mostransport-hakaton.git
cd mostransport-hakaton/service
docker compose up -d --build
```

Через 30 секунд откройте http://127.0.0.1:8080 и войдите демо-аккаунтом **`demo` / `demo2025`**.
Можно зарегистрировать своего пользователя на вкладке «Регистрация» в той же форме.

| Что | Адрес |
|---|---|
| Интерфейс диспетчера | http://127.0.0.1:8080 |
| REST API | http://127.0.0.1:8123 |
| Документация API (Swagger) | http://127.0.0.1:8123/docs |
| Состояние сервиса | http://127.0.0.1:8123/health |

- Поднимаются три контейнера: `api` (движок прогноза и API, 4 vCPU / 4 ГБ), `web` (интерфейс) и `db` (PostgreSQL).
  Конфигурация — [`service/docker-compose.yml`](service/docker-compose.yml). Минимальная конфигурация ТЗ (2 vCPU / 2 ГБ):
  `docker compose -f docker-compose.yml -f docker-compose.2cpu.yml up -d --build`.
- Открывайте адрес с `http://`, а не `https://`. Если страница не открывается, проверьте `docker compose ps`
  в каталоге `service`.
- Раздел «Качество прогноза» заполняется через 2 минуты после старта.
- Данные заканчиваются 31.10.2025, поэтому «сегодня» на стенде — 1 ноября 2025 года, время суток — московское.
- Вход обязателен: без токена API данных не отдаёт. Пароли хранятся в PostgreSQL в виде хеша, сессия — токен JWT.
  Отдельной роли администратора пока нет.

## Что умеет

| Раздел интерфейса | Что показывает |
|---|---|
| Обзор | прогноз за период с коридором, пиковый час, нагрузка по маршрутам, маршруты с риском |
| Оперативная ситуация | текущий час и три следующих; рекомендации вроде «добавить 6 вагонов к 7:00» с кнопками «Принять / Позже / Отклонить» |
| Журнал решений | принятые, отложенные и отклонённые рекомендации |
| Карта и остановки | маршруты на карте Москвы и оценка посадок по 449 остановкам |
| Загрузка вагонов | обычный и рекомендуемый выпуск, часы риска переполнения |
| План выпуска | вагоны по часам на 7 дней вперёд с причиной, экспорт в Excel |
| Качество прогноза | прогноз против факта; на реальном октябре 2025 — 0,908 |

В «Параметрах» задаются период (день, месяц, год), маршруты, часы и сценарий «что если» — он пересчитывает прогноз,
рекомендации и план. Любую таблицу можно выгрузить в CSV или Excel.

Сервис сам применяет модель и скачивает внешние данные, принимает новые данные через API и сам пересчитывает прогноз.

## API

| Запрос | Что делает |
|---|---|
| `POST /auth/token`, `POST /auth/register` | вход и регистрация |
| `GET /forecast`, `GET /forecast/export` | прогноз с коридором по датам, маршрутам и часам; выгрузка CSV / XLSX |
| `GET /now`, `GET /alerts` | оперативная ситуация и рекомендации |
| `GET /fleet`, `GET /plan`, `GET /plan/export` | загрузка вагонов и план выпуска |
| `POST /decisions`, `GET /decisions/report` | журнал решений |
| `GET /monitor/accuracy` | точность прогноза на поступивших фактах |
| `POST /ingest/hourly`, `POST /ingest/validations` | приём новых данных |
| `GET /model/info` | дата данных, горизонт, источники внешних данных |

Примеры запросов — [docs/JURY.md](docs/JURY.md).

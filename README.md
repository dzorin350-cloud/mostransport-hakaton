# Хакатон МТТЕХ: прогноз посадок в трамваях Москвы

> **Жюри:** запуск и проверка — [docs/JURY.md](docs/JURY.md). **Команда:** статус и что осталось — [docs/STATUS.md](docs/STATUS.md). Внешние данные — [docs/EXTERNAL_DATA.md](docs/EXTERNAL_DATA.md),
> область определения и адаптации — [docs/APPLICABILITY.md](docs/APPLICABILITY.md), все прогоны и тесты — [docs/TESTS.md](docs/TESTS.md).

Почасовой прогноз посадок на 10 маршрутах трамвая (маршрут × дата × час).
**Модель v7, лидерборд 0,88399 (WAPE-score).** Подробное описание — в [ARCHITECTURE.md](ARCHITECTURE.md).

Прогноз = уровень маршрута × форма дня (CatBoost + профиль) × сезонный множитель месяца; обучение на данных, очищенных от перекрытий и разовых сбоев.

**Веб-сервис** (REST API + дашборд с картой, требование ТЗ п.3–4) — в
[`service/`](service/README.md). Быстрый старт: `cd service && docker
compose up -d --build`, дашборд на http://localhost:8080. Нагрузочный тест:
в смешанном профиле диспетчера (прогноз, алерты, план, остановки, мониторинг, XLSX):
≈ 395 RPS при CPU ~60–64 %, p95 72 мс на 4 vCPU / 4 ГБ (10 минут, ≈ 236 тыс. запросов, 0 ошибок) и
≈ 174 RPS при CPU ~73 %, p95 110 мс на 2 vCPU / 2 ГБ (60 секунд). В прежнем более лёгком профиле только прогноза было ≈ 995 RPS, p95 40 мс.
Это замеры чтения при стабильной версии прогноза. При одновременной загрузке фактов и пересчёте отдельный тест показал
p95 **1,43 с** в коротком окне пересчёта при 100 пользователях — требование для этой фазы пока не выполнено
([подробности и сырые результаты](docs/TESTS.md)). Сервис сам применяет модель и сам скачивает внешние данные —
[`service/engine/README.md`](service/engine/README.md). Все прогоны и тесты — [`docs/TESTS.md`](docs/TESTS.md).

**Для фронтенда:** что учитывает модель и что показывать пользователю — [`service/FRONTEND_NOTES.md`](service/FRONTEND_NOTES.md).

## Структура

```
service/               веб-сервис: API (FastAPI) + дашборд (карта, коэффициенты, экспорт)
                       см. service/README.md — отдельный запускаемый компонент
v7/
  code/
    final_v7.py        воспроизводит отправленный сабмит v7 (замороженный код)
    forecast.py        продовый прогноз на любой горизонт: день, месяц, год (до 12 месяцев)
    fetch_external.py  обновляет внешние данные из интернета (календарь, сезонность)
    build_grid.py      собирает почасовую сетку из labels/
    clean.py           очистка обучения
    pipe.py            CatBoost, профиль, сезонные множители
    model.py           данные, календарь, метрика
    best_params_final.json   параметры CatBoost (Optuna)
  data/                ridership_allowed.csv (сезонность), test_submission.csv (шаблон сетки), submission_v4.csv
  submission_v7.csv    отправленный файл (лидерборд 0,88399), md5 в submission_v7.md5
  output/              сюда пишутся результаты
labels/                почасовая разметка организаторов (train: янв–авг, test: сен–окт 2025)
external/              внешние данные: календари isdayoff (cal_YYYY.txt), data.mos.ru (mos/),
                       события Дептранса (events_trams_2025.csv), погода (справочно)
experiments/           скрипты всех экспериментов (см. ниже)
forecast_year_2025-11_2026-10.csv   годовой прогноз
```

## 1. Воспроизвести v7

Нужен Python 3.13.

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cd v7/code
python build_grid.py          # labels/ → data/grid.parquet
python final_v7.py            # → ../output/submission_v7.csv
md5 ../output/submission_v7.csv   # на Linux: md5sum; должно совпасть с ../submission_v7.md5
```

Обучение занимает около 5 минут (5 моделей CatBoost). Проверено: результат совпадает с отправленным файлом байт в байт (macOS, Apple Silicon, `thread_count=10`). На другом железе CatBoost может дать отличия в последних знаках, на скор это не влияет.

Сырые `train.csv` и `test.csv` (10 ГБ) не нужны: модель обучается на `labels/`.

## 2. Продовый прогноз

`forecast.py` — та же модель v7, но горизонт задаётся параметрами, а внешние данные могут подтягиваться из интернета.

```bash
cd v7/code
# месяц (ноябрь–декабрь 2025): совпадает с submission_v7.csv байт в байт
python forecast.py --start 2025-11-01 --end 2025-12-31 --out ../output/forecast.csv
# один день
python forecast.py --start 2025-11-12 --end 2025-11-12
# год (до 12 месяцев от конца обучающих данных)
python forecast.py --start 2025-11-01 --end 2026-10-31
# сначала обновить календарь и сезонность из интернета
python forecast.py --refresh --start 2025-11-01 --end 2025-12-31
```

Выход: CSV `route;date;hour;prediction`, маршрут 5 всегда 0.

### Внешние данные в проде

| Данные | Источник | Что делает `fetch_external.py` | Если источник недоступен |
|---|---|---|---|
| Производственный календарь | [isdayoff.ru](https://isdayoff.ru/api/getdata?year=2026) | скачивает 2022–2025, текущий и следующий год в `external/cal_YYYY.txt` | используется кэш из репозитория (есть 2022–2027) |
| Месячный пассажиропоток трамвая | [data.mos.ru, набор 62521](https://data.mos.ru/opendata/62521) (адрес выгрузки в `external/mos/meta_62521.json`) | скачивает свежую выгрузку и **оставляет только месяцы до конца обучающих данных** (защита от утечки) | используется кэш `ridership_allowed.csv` |

data.mos.ru открывается только с российских адресов. Загрузка календаря проверена; загрузка data.mos.ru не проверена (с нашей сети сайт недоступен), при ошибке скрипт оставляет кэш и не падает.

### Docker

```bash
docker build -t tram-forecast .
docker run --rm -v "$PWD/v7/output:/app/v7/output" tram-forecast
# другой горизонт:
docker run --rm -v "$PWD/v7/output:/app/v7/output" tram-forecast --start 2025-11-01 --end 2026-10-31 --out /app/v7/output/year.csv
```

По умолчанию контейнер обновляет внешние данные (`--refresh`) и строит прогноз на ноябрь–декабрь 2025. Dockerfile не проверялся локально (Docker не установлен).

### Как встраивать в сервис
- **Обучение** (`clean_grid` → `fit_cb` × 5 → профиль, уровни маршрутов, множители) — пакетно, раз в неделю или при поступлении новых данных.
- **Новые данные:** заменить `labels/` почасовыми агрегатами валидаций (`route;date;hour;boardings`) до последней полной даты и пересобрать сетку `build_grid.py`. Сейчас список маршрутов и начало данных (2025-01-01) заданы в `build_grid.py`.
- **Прогноз** по готовым артефактам дешёвый (миллисекунды). Структура мультипликативная, поэтому корректирующие коэффициенты (сезон, погода, событие) можно применять поверх прогноза.
- **Ограничение:** горизонт до 12 месяцев от конца обучающих данных.

## 3. Эксперименты

`experiments/` — все скрипты исследования: EDA, Optuna, очистка, события Дептранса (`tg2.py`, `events.py`), погода (`rain*.py`), синтетика (`synth.py`), годовой прогноз (`year_*.py`), варианты v3–v8. Пути в них указывают на рабочую папку сессии, поэтому они приведены как документация, а не как готовые к запуску. Дополнительные библиотеки: `experiments/requirements-extra.txt`.

# ИИ-прогноз загрузки трамвайных маршрутов Москвы

Хакатон МТТЕХ. Почасовой прогноз посадок по 10 маршрутам трамвая на горизонт от дня до года и рабочее место диспетчера,
которое превращает прогноз в решения: где и когда ждать давки, сколько вагонов выпустить, что делать сейчас.

**Итоговая модель — WAPE-score 0,88960 на лидерборде** (ноябрь–декабрь 2025).
Прогноз = уровень маршрута × форма дня (CatBoost с длиной светового дня + профиль) × сезонный множитель месяца (свой для маршрута); обучение на истории,
очищенной от перекрытий и сбоев. Подробно — [docs/MODEL.md](docs/MODEL.md), [ARCHITECTURE.md](ARCHITECTURE.md).

## Запуск веб-сервиса (Docker Compose)

Нужны Docker с Docker Compose и доступ в интернет (без интернета сервис работает на встроенных копиях внешних данных).

```bash
git clone https://github.com/dzorin350-cloud/mostransport-hakaton.git
cd mostransport-hakaton/service
docker compose up -d --build
```

| Точка входа | Адрес |
|---|---|
| Интерфейс диспетчера | http://localhost:8080 — демо-аккаунт **`demo` / `demo2025`** (или «Регистрация») |
| REST API | http://localhost:8123 |
| Документация API (Swagger) | http://localhost:8123/docs |
| Проверка состояния | http://localhost:8123/health, `/ready` |

- Конфигурация: [`service/docker-compose.yml`](service/docker-compose.yml) — три контейнера: `api` (движок прогноза и FastAPI,
  4 vCPU / 4 ГБ), `web` (интерфейс React, nginx), `db` (PostgreSQL). Минимальная конфигурация ТЗ (2 vCPU / 2 ГБ):
  `docker compose -f docker-compose.yml -f docker-compose.2cpu.yml up -d --build`.
- Готовность — через ~30 с после старта (`docker compose ps` → `api … (healthy)`); раздел «Качество прогноза» заполняется
  через ~2 минуты. Остановить: `docker compose down`.
- **Вход с аутентификацией:** при открытии http://localhost:8080 появляется форма входа с двумя вкладками. «Вход» —
  логин и пароль (демо-аккаунт `demo` / `demo2025` создаётся при старте). «Регистрация» — новый пользователь прямо в этой же
  форме: логин латиницей от 3 символов, пароль от 6 символов, после регистрации вход выполняется сразу. Пользователи хранятся
  в PostgreSQL (пароли — хеш PBKDF2), сессия — токен JWT (OAuth2 Password Flow), кнопка выхода — внизу меню. Без входа
  данные не отдаются; через API — `POST /auth/register`, `POST /auth/token`, заголовок `Authorization: Bearer <токен>`.
- **Демо-время:** данные заканчиваются 31.10.2025, поэтому «сегодня» на стенде — 01.11.2025 (первый день прогноза),
  время суток — московское. В проде — `NOW_MODE=real`.

## Возможности

**Интерфейс диспетчера** (React, карта MapLibre):
- **Обзор** — прогноз посадок за период, маршруты с риском, пиковый час, динамика с коридором 80 %, нагрузка по маршрутам,
  состояние маршрутов с выпуском вагонов.
- **Оперативная ситуация** — текущий час и 3 следующих по маршрутам; рекомендации с действием («добавить до 6 вагонов к 7:00»,
  «можно снять 5 вагонов», праздник, сильный дождь) и кнопками «Принять / Позже / Отклонить».
- **Журнал решений** — принятые, отложенные и отклонённые рекомендации (PostgreSQL).
- **Карта и остановки** — маршруты на карте Москвы и оценочные посадки по 449 остановкам.
- **Загрузка вагонов** — обычный и рекомендуемый выпуск, часы риска переполнения.
- **План выпуска** — маршрут × час на 7 дней: прогноз с коридором, «обычно → рекомендуем», причина; экспорт в XLSX.
- **Качество прогноза** — прогноз, сделанный до факта, против факта (реальный октябрь 2025: 0,905).
- **Параметры и сценарии** — период (день / месяц / год), маршруты, часы, сценарий «что если» (коэффициент), который
  пересчитывает прогноз, рекомендации и план. Экспорт CSV / XLSX у каждой таблицы.

**Сервис:** сам применяет модель и сам скачивает внешние данные (календарь, сезонность, прогноз осадков), принимает новые
данные через API и пересчитывает прогноз, хранит версии прогноза для контроля точности, восстанавливается после сбоя,
авторизация OAuth2 + JWT, ошибки на русском.

## API

| Эндпоинт | Назначение |
|---|---|
| `POST /auth/token`, `POST /auth/register` | вход (OAuth2 Password Flow → JWT), регистрация |
| `GET /forecast`, `GET /forecast/export` | прогноз с коридором 80 %: даты, маршруты, часы, детализация `hour/day/week/month`, сценарий `coefficient`; экспорт CSV / XLSX |
| `GET /now`, `GET /alerts` | оперативная ситуация и рекомендации диспетчеру |
| `GET /fleet`, `GET /plan`, `GET /plan/export` | загрузка вагонов, план выпуска, XLSX |
| `POST /decisions`, `GET /decisions/report` | журнал решений |
| `GET /monitor/accuracy` | точность прогноза на поступивших фактах |
| `POST /ingest/hourly`, `POST /ingest/validations` | приём новых данных → автоматический пересчёт |
| `GET /stops`, `GET /forecast/stops` | остановки и оценочный прогноз по ним |
| `GET /model/info` | дата данных, горизонт, множители, источники внешних данных и их статус |

Примеры запросов curl и полный список — [docs/JURY.md](docs/JURY.md); технические подробности сервиса — [service/README.md](service/README.md).

## Структура репозитория

```
service/        веб-сервис: движок прогноза, API (FastAPI), интерфейс (React), Docker Compose
  engine/         применение модели, внешние данные, пересчёт; artifacts/ — 10 моделей CatBoost
  api/            API, авторизация, хранилище (PostgreSQL), тесты, нагрузочные тесты и их отчёты
  web/            интерфейс диспетчера
model/          итоговая модель: код обучения, отправленный сабмит и его md5
labels/         почасовые посадки январь–октябрь 2025 (исходные данные)
external/       внешние данные: календарь, сезонность data.mos.ru, ремонты Дептранса, погода
experiments/    журнал экспериментов (не рабочий код)
docs/           документация
Dockerfile      пакетный прогноз итоговой моделью без сервиса
```
